学术界在研究什么

TOPICS & REPRESENTATIVE WORK
105 papers · #1

1. 评价：从“最终答对”到“过程可信”

研究重点是长时程、动态环境、真实软件/网页、可验证结果，以及轨迹级失败归因。难点不再只是做数据集，而是避免污染、处理环境漂移，并让 verifier 真能反映业务成功。

  • Can Agent Benchmarks Support Their Scores?
  • AgentPulse: Evaluating AI Agents in Deployment
  • Claw-Eval-Live: A Live Agent Benchmark
入门代表：WebArena (ICLR 2024)、SWE-bench (ICLR 2024)。
84 papers · #2

2. 训练：轨迹、过程奖励与自我改进

把 agent 的多步交互轨迹转成训练信号：RL、过程奖励、失败轨迹学习、经验回放、技能发现和合成数据。核心矛盾是长 horizon 的信用分配、奖励作弊与昂贵环境交互。

  • Agentic-DPO
  • Beyond Outcome Rewards
  • AlphaSkill: Self-evolving Skills
建议基础：先理解行为克隆、PPO/GRPO、过程监督；再复现一个小模型 agent 的离线轨迹学习，别从昂贵在线 RL 起步。
73 papers · #3

3. 工具使用、规划与 Computer Use

让模型决定何时调用哪种工具、如何填参数、观察结果后如何重规划。2026 趋势是从文本 API 扩展到 GUI、代码仓库和混合模态环境，重视依赖关系、状态管理与终止判断。

  • CODA: Dual-Brain Computer Use Agent
  • Agentic Planning under Dependency-Preserving Augmentation
  • AgentEscapeBench
入门代表：ReAct (ICLR 2023) 与 Toolformer (NeurIPS 2023)。
64 papers · #4

4. Memory 与长时程状态

不只是向量库：研究写入/检索/压缩/遗忘策略，情景记忆与技能记忆的分工，跨任务记忆污染，以及“记住了但行为没更新”。工业上直接对应上下文成本和重复工作。

  • Agentic Memory Engineering
  • EvolveMem
  • Auto-Dreamer: Offline Memory Consolidation
好的研究问题不是“加 memory 是否涨分”，而是固定 token/延迟预算下，哪种写入和淘汰策略改善长期任务成功率。
62 papers · #5

5. 安全、隐私与运行时可靠性

Prompt injection、恶意工具、越权、隐私泄漏、虚假完成、不可逆动作、监控与可恢复执行。产业真正关心的是部署时的 capability control 和审计证据，而不只是拒答率。

  • Auditing Agent Harness Safety
  • AttChain: Hijacking Agent Tool Chain
  • Learned Capability Governance
强选题形态：威胁模型 + 可复现实验环境 + 攻击集 + 防御 + 效用/成本副作用，而非只做 prompt 分类。
47 papers · #6

6. 多 Agent：何时协作，何时只是更贵

研究角色分工、路由、通信、冲突和共识失败。热点正从固定角色 prompt 转向动态团队与资源分配；关键 baseline 必须包含“同等 token 的单 Agent”，否则收益可能仅来自更多采样。

  • Latent Multi-Agent Collaboration
  • False Convergence in Multi-Agent LLMs
  • Evolving Agent Teams
适合做系统/算法，但不建议把“多 Agent 框架搭建”本身当创新；需要成本控制、消融与失败机制分析。

首推 · 论文与求职兼顾

Agent 轨迹级故障检测与自动恢复

面向 coding/web/data agent，把失败定位到 observation、plan、tool call、verification 或 termination，并触发最小成本恢复。

可做性9
工业价值10
  • 研究问题：仅用 trace 能否早于最终失败检测？哪种恢复策略在固定预算下最好？
  • 最小交付：1 个 benchmark、失败 taxonomy、检测器、replay/replan/ask-human 三类恢复。
  • 亮点：可与 observability、SRE、评测平台直接衔接。
建议范围：选一个环境（SWE-bench 子集或自建可验证数据任务），不要横跨所有 Agent。
高性价比

成本约束下的动态模型/工具路由

根据任务状态选择小/大模型、检索、代码执行或人工确认，在成功率、token、延迟之间做 Pareto 优化。

可做性9
工业价值9
  • 对比固定路由、置信度路由、contextual bandit。
  • 指标必须含 task success、p95 latency、美元成本与失败风险。
  • 可用开源小模型 + 少量商业 API，算力要求较低。
论文贡献要落在“状态表征/在线决策/不确定性”，不是写一套 if-else。
稳健 · 易落地

预算感知的长期记忆写入与淘汰

研究什么值得记、何时压缩或遗忘，并防止错误经验污染；用持续变化任务而非静态 QA 评测。

可做性9
工业价值8
  • 建立“信息效用 × 新鲜度 × 风险 × token 成本”的写入分数。
  • 设计概念漂移和矛盾更新测试。
  • baseline：全文上下文、RAG、摘要、LRU、反思式记忆。
不要只做新的向量检索公式；长期状态更新与可撤销性更有价值。
安全方向

Tool-use Agent 的最小权限与运行时策略

根据当前计划动态授予最小工具能力，对高风险动作做 typed contract、dry-run 或 human-in-the-loop。

可做性8
工业价值10
  • 威胁：间接 prompt injection、参数越权、工具链投毒。
  • 测量：攻击成功率、正常任务保留率、额外延迟与人工打断率。
  • 适合安全/系统背景，有明确工程产物。
范围控制在一种工具环境；完整企业权限系统对硕士论文过大。

为什么不报“官方 7,900”

第三方页面声称 30,709 投稿、7,900 录用，但截至截点，NeurIPS 官方公开页没有给出可核验的最终总表。用户听到的“3 万篇中了 6k–7k”数量级合理，但严肃报告不应把未经官方确认的数字写成事实。

因此本页只用 7,012 快照作趋势抽样，并同时给出 2025 官方已确认基线：主赛道 21,575 篇有效投稿、5,290 篇录用（24.5%）。
